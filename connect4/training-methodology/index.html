Lab / Connect 4 interface notes

What the code tells us.

A concise account of the verified frontend implementation and the evidence still needed for the models.

Browser and API

The browser enforces gravity and checks four-in-a-row in both diagonal directions, horizontally, and vertically. It sends numeric boards to a separate inference service with identifiers transformer, cnn, or pg. The API returns a column.

Three routes, not a measured ranking

Casual, Challenge, and Insane are existing mode labels. The previous explainer described two models, but the interface has three routes. This repository does not contain architecture code, training data, checkpoints, or evaluation logs.

Fallbacks and state

A failed move request falls back to a random legal column. An invalid returned column falls back to the first legal column. Local storage keeps per-opponent and combined results. These records do not distinguish inferred and fallback moves and cannot be used as model benchmarks.

Training and evaluation

The prior self-play and evaluation narrative could not be verified from source. Training details are pending backend documentation. The case study records the evidence gaps and a possible reproducible comparison protocol.
